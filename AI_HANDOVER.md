## 2. Owner's vision and non-negotiables

WorldCraft is a **native standalone procedural open-world creator, explorer and optional editor**, not a Minecraft clone, a web app, or just a heightmap tool. A user should create a seed and immediately walk/fly through breathtaking nature. Editing should feel as approachable as WorldPainter, with advanced controls available but not forced. The intended level is cinematic AAA / near-photorealistic terrain, with extreme natural variation from procedural rules rather than a handful of handcrafted demo scenes.

- Native Rust; preserve independent deterministic world core, maintainable rendering/editor boundaries and old saves. Bevy is a means to the goal, not a requirement to rewrite everything in a custom renderer.
- Development, downloads, dependencies, compilation, QA and packaging must use hosted/cloud environments and standard free public-repository CI runners. **Do not use the owner's computer for development or large checkouts**; the owner explicitly cited storage and speed. Do not buy anything, use paid runners/APIs, alter spending or weaken security. Deliver Windows x64 installer/portable test builds to the owner.
- Exploration first; low-end support is important. Automatic launch hardware calibration and runtime adaptation should aim for at least 30 FPS where feasible, not guarantee it. Provide manual controls; maintain high-end options, aggressive culling, bounded multithreaded streaming and smooth transitions.
- Continuous perceived quality: near high detail, farther lower detail, no conspicuous rings, pops, seams or density walls. Internal discrete mesh resolutions are acceptable only with well-tested morph/fade endpoints.
- Owner explicitly requests: all eligible world surfaces up to native 4K textures, PBR + POM, rich terrain/rock/ground litter/foliage variety, realistic lighting and shadows, visibly effective volumetrics and godrays, beautiful sky/clouds, time-dependent fog, weather, rivers/lakes, real erosion, snowy mountains, deserts, badlands, volcanoes, lush forests, blended temperature/humidity biomes, dense understory, realistic water/fire/smoke with physics, and spatial nature ambience/sound ray tracing. Include ray-traced and raster paths, DLSS SR, DLAA, FSR 4.1; path tracing is a future quality option, not a delivered feature.
- Procedural generation should be the default. Optional CC0 scans and licensed assets may supplement it; Canva/third-party tools were permitted, not mandatory. Record provenance/licenses. Never use generated illustrations or reference frames as proof of actual engine rendering.
- Iterate promptly in meaningful vertical slices. The owner was unhappy with slow realism gains and repeatedly requested rapid visible improvement, higher-resolution foliage/ground and working volumetrics, not just more switches or percentage claims. Audit major milestones, produce native screenshots, publish tested builds and keep documentation current. When blocked, diagnose and find safe bounded workarounds; do not quietly remove tests or claim success.
- References: [JangaFX GeoGen](https://jangafx.com/software/geogen), [landscape video 1](https://www.youtube.com/watch?v=v-RZP5UXCsE), [video 2](https://www.youtube.com/watch?v=uR5EvBWxN14), [video 3](https://www.youtube.com/watch?v=mUl1QxCCAAQ), and owner-supplied reference images in earlier conversations (cinematic conifer valley, waterfalls/rivers, snowy mountains, forest floor, warm coast). Terrain Diffusion is a technical reference/backend; do not claim its full pipeline has been reproduced. Earlier suggested libraries included bevy_generative, rayon, fast-noise-lite-rs, terra and serde; verify actual dependencies rather than treating suggestions as mandates.

## 5. Architecture and actual data contracts

Workspace: Rust 2021, pinned Bevy 0.20.1 / bevy_egui 0.43.1 foundation, wgpu, winit, Vulkan/DX12. Later NVIDIA/AMD integration uses patched vendored bevy_render (read WORLDCRAFT_PATCH.md); verify lockfile before changing versions. No Python or Java runtime required. Python scripts are build-time asset/QA tooling. Avoid dependency churn until a reproducible baseline exists.

| Component | Responsibilities / entry points |
|---|---|
| crates/worldcraft-core | config, generation, geology, erosion, ecology, estuary, regional, mesh, scatter, continuous LOD, streaming coordinates, edit history, persistence, export, vista, adaptive and hardware policy. No window/GPU dependency. |
| crates/worldcraft-ml | assets, scheduler, detail, detail_math, lib; checksum-pinned ONNX models and sequential CPU inference; audit/detail-audit/detail-probe binaries. |
| crates/worldcraft | main ECS wiring; session, storage, control, ui, streaming, vista; scene, capabilities, render_options, render_quality, calibration, performance; surface shaders, sky_post, clouds, ground_surface, texture_pack, relief_texture, terrain_texture, nature_texture; tree, foliage, canopy, understory, skyline, assets; raytrace; fsr/fsr_ffi/fsr_native; verify + render/relief/biome/nature audit modules. |
| tools / .github/workflows | Material generators, pinned SDK/ORT/DXC bootstrap, native checks, image gates, benchmark scripts, installer and packaging, publication, Pages. |

Verified source structure at 15ad6dec:
- `GeneratorSettings` = seed u64, preset, sea_level, vertical_scale, terrain_scale, mountain_strength, river_strength, vegetation, temperature, rainfall (numeric fields f64). Preset enum Temperate, Alpine, Tropical, Desert, Arctic, Islands, Savanna, Volcanic, Empty, Estuary.
- `WorldFile` format_version=3, generator_version, name, settings, settings_hash u64, optional LearnedRegion, edits Vec<Vec<Stroke>>, camera [f64;3], yaw/pitch f32. JSON file .worldcraft.json; format version and generator version independent. Generator version currently 3; maintain v1/v2 geography and scatter exactly. Future changes altering seed geography must be explicitly versioned; don't silently upgrade old worlds on open/save/undo.
- `Sample` has height, temperature, moisture, biome and vegetation. 14 Biome variants: Ocean, Beach, Grassland, Forest, Rainforest, Conifer, Desert, Tundra, Snow, Volcanic, Savanna, Wetland, Meadow, BirchForest. Label is dominant; material/probability blends are continuous.
- `Generator` owns settings, ordered strokes, version, spatial index HashMap<(i64,i64),Vec<usize>>, shared Arc<TerrainCache>, optional Arc<LearnedRegion>. Immutable snapshots passed to workers. 512 m erosion tiles with 64 cells + shared edge, 8 m lattice, 18-cell halo, 8 thermal iterations, threshold .60 and coefficient .045; shared bounded 32-tile LRU (~1.03 MiB retained f64 heights, not peak memory). Single-flight region bake; brush replay after erosion.
- `Stroke` = center [f64;2] + Brush (kind, radius, strength, target_height, biome, density). BrushKind Raise/Lower/Flatten/Smooth/Terrace/Biome/Vegetation. EditHistory transactions and redo are Vec<Vec<Stroke>>, revision u64. Spatial indexing at 256 m preserves operation order. Smooth uses stored target; no automatic hydraulic re-simulation. History/checkpoint scaling still open.
- 128 m chunks, ChunkCoord x/z i64; internal 32/16/8/4 cells per side with geometric morph, shared boundary and skirts. Persistent f64 coordinates limited ±1e9 m, GPU local f32; render origin moves by 256 m increments. No mathematical infinity. Preserve negative coordinates, seams and world-space material/wind anchors after rebase. Vista uses bounded clipmap job and horizon water; far mesh not identical full erosion.
- `Session` world Option<WorldFile>, generator Option<Arc<Generator>>, history, epoch/revision, chunk_revisions map, dirty, path, origin DVec3, mode Walk/Fly/Edit. `Player` position DVec3, yaw/pitch, velocity, grounded/captured. ECS and GPU resources main-thread-owned; worker outputs validated on epoch, revision, detail, eco and relevant request IDs before upload.
- `Stream` loaded HashMap<ChunkCoord,Loaded>, pending tasks, desired/last_ms/triangles/far_triangles, epoch, launch time, settled and eco. Loaded retains entity/key/terrain mesh/foliage entity/colliders/triangles/detail/eco. Build can return optional MeshData, instances, 32m ground mesh batches, skyline mesh. TilePlan caches epoch/revision/observer/radius/eco. Foliage-only invalidation retains terrain. Count all outstanding stale synchronous jobs until completion.
- Ecology uses 8 m canopy/rock lattice, 2 m near ground lattice; at most 256 canopy/rock + 4096 ground candidates per chunk (4,352 bound). Hash-based admission and shared prototypes, no per-grass entity or material. Five tree families x four prototypes. Maintain exact legacy placements. Far silhouettes through 1,536 m, near detail by 480 m, outer taper 1280–1536 m, Eco skips far trees. Wind shader exists for raster/depth/shadow; ray proxies static and wind paused in ray mode.
- `Graphics`: ray_tracing, quality Low/Balanced/High, radius, hour/cycle, fog/breeze, volumetrics/clouds, mist_height/density, exposure/map. `RenderOptions`: upscaler Auto/Native/Dlss/Dlaa/Fsr41; AA Off/FXAA/SMAA/TAA; output scale, sharpening, quality, shadows/AO, bloom, tone map AgX/TonyMcMapface/ACES/Reinhard, saturation/contrast, FOV, DOF, surface source/resolution Automatic/1K/2K/4K, relief Off/Balanced/Ultra, cloud/fog steps, vsync, backend Auto/Vulkan/DX12. Check active provider separately from requested selection.
- Physics: ground collision uses triangulated near terrain; conservative object cylinders, gravity/jump/step and bounded substeps; no general rigid-body physics, caves, dynamic water or fire.
- LearnedRegion stores finite coarse and optional detailed height field; exact layout in regional.rs and detail.rs. Fast optional ~22.5 MB coarse model; detailed ~2.28 GB set pinned checksums; load/drop sessions sequentially, 6 GiB available RAM admission. No inference on streaming/edit replay/reopen. CPU fixture ~4.43 GiB peak RSS, not universal. Full neighboring-window learned streaming and GPU inference unfinished.
- Persistence: atomic replacement plus .json.bak; recovery and recents under %LOCALAPPDATA%/Worldcraft or XDG_DATA_HOME/worldcraft / ~/.local/share/worldcraft. Installer leaves user data/models intact. Never overwrite user worlds for testing. GLB and 16-bit height export already audited.

### P1 — visible AAA graphics improvement, immediate owner priority
- Improve sky physically: correct sunlight/sky energy, exposure consistency, aerial perspective, cloud lighting/shape, weather-dependent coverage, coherent shadows, night/moon/stars. Better dawn/dusk and time-dependent valley fog. Preserve cloud/AA/AO-independent depth requirement and zero-density toggle. Make shafts spatially meaningful, not a screen overlay. - Make the 4K texture tier visually worthwhile: real high-frequency detail, albedo without baked light, physical roughness, normals/height/AO, optional material blending/triplanar mapping, fewer repeating tiles, slope/altitude/biome transitions. Maintain appropriate mip filtering/compression/streaming; 4K map size alone does not mean realism. Use POM selectively, with stable grazing angles and motion; avoid sampling every layer everywhere. Make ray/shadow material behavior consistent or document approximation.
- Ground-level nature: authentic scale and dense variation in litter, grass, rocks, fallen wood, ferns, flowers, branches, bark and leaves. Improve silhouette, foliage transmission/subsurface approximation, contact shading and wind; use shared instanced prototypes and habitat-driven variations, not thousands of unique entities. - Water: realistic shallow/deep color, depth absorption, reflections/refraction with raster fallbacks, wind ripples, shoreline foam, wet/dry material blending. Current estuary is static sea-level heightfield; dynamic flow, tides and rivers are separate simulation tasks. Don't call PBR water fluid physics.

Budget geometry, texture bytes, frame-time tails and queue. Don't just add UI toggles. Aim toward 80/100 visual quality first, then the owner's aspirational 100/100; no objective guarantee.

## 8. Acceptance and operating checklist

Every meaningful change: state target → inspect existing code → implement coherent vertical slice → run focused regressions and workspace checks → actual native render/interaction tests → measure and compare against frozen baseline → inspect screenshots and failures → update docs/evidence and PR → provide Windows candidate when suitable. Maintain user-facing controls, no regressions in old saves or generator identities. Keep one bounded job per scarce resource, cancel safely, count stale tasks; never weaken assertions to get green CI. Mark untested, unsupported and planned functionality separately from delivered functionality.

Visual rubric (proposed consistent review): terrain/geology, vegetation/ecology, material/close detail, atmosphere/lighting, water/world coherence each 0–4; sum/20 × 100. Document representative native images and weaknesses, reviewer judgment rather than fabricated objective percentage. Include temporal stability and resource costs separately.
